Tool

Team Access

See who has access. Apply the roster you intended.

For GitHub repository maintainers. Team Access compares a YAML roster with collaborators and invitations, shows permission drift and applies the changes you authorize through the stable addteam command.

Use Team AccessWatch the 72-second filmWalk through an example

Keep one readable roster

Use named role groups in team.yaml rather than remembering individual invitations and permission settings.

Review drift before changing access

Audit or dry-run additions, permission changes and removals before an apply operation.

Use it across repositories

Reuse a central roster or inspect several repositories while keeping the target repository explicit.

Limits and prerequisites
  • Native addteam remains the executable and import namespace; no coaching skill or hidden invitation automation is introduced.
  • Audit/dry-run may read GitHub; tests use mocks and do not invite users, accept invitations, change permissions or send welcome issues.
  • A removal circuit breaker is an operational limit; it does not itself authorize any access change.
